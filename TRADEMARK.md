# Arbiter Trademark Policy

"Arbiter" and the Arbiter project name are unregistered trademarks of the Arbiter Project. This policy clarifies how the name may be used and complements the Apache License 2.0 that covers the source code and documentation. Apache 2.0 Section 6 already withholds any grant of trademark rights; this policy states what use of the name **is** permitted.

## Short version

You can refer to the project, fork the code under Apache 2.0, and discuss the project freely. You cannot use "Arbiter" to brand your own commercial product, suggest endorsement by the project, or pass a fork off as the official project.

## What is permitted

- **Nominative use** — referring to the project by name (e.g., "built using Arbiter", "fork of Arbiter", "compatible with the Arbiter API")
- **Discussion and reference** — blog posts, tutorials, academic papers, talks, comparative reviews
- **Unmodified redistribution** — redistributing the project as-is under Apache 2.0, retaining the original name, the `LICENSE` and the `NOTICE`
- **Personal and internal use of forks** — using a renamed fork inside your own organization

## What requires permission

- **Commercial products or services branded "Arbiter"** or using "Arbiter" as part of a product name (e.g., "Arbiter Cloud", "Arbiter Enterprise", "Arbiter for X")
- **Modified distributions retaining the "Arbiter" name** — substantial forks offered to third parties must be renamed to avoid confusion with the official project
- **Use suggesting endorsement** — any phrasing implying the Arbiter Project endorses your product, fork, or service
- **Domain names, logos, social media handles** incorporating "Arbiter" for commercial purposes

## What is prohibited

- Use of "Arbiter" in a way that competes with the official project under the same name
- Use designed to confuse users about whether your product is the official Arbiter
- Use that disparages the project or its maintainers

## Code license is Apache 2.0

The Apache License 2.0 (see [LICENSE](LICENSE)) covers the Arbiter source code and documentation. You may freely fork, modify, distribute, and sell software built from Arbiter source code under Apache 2.0 terms — retaining the `LICENSE` and `NOTICE` and stating your changes, as that licence requires — you simply cannot call the resulting product "Arbiter" or imply official endorsement.

The choice of Apache 2.0 is load-bearing for this policy rather than incidental: it reserves trademark rights in the licence text itself, which is the premise this policy rests on. A permissive licence silent on trademarks — MIT, for instance — would not support it.

## Requesting permission

For commercial-naming, branding, or other permissions outside the scope above, use the private channel described in [SECURITY.md](SECURITY.md) (GitHub Private Vulnerability Reporting routes to maintainers and is the appropriate intake for any inquiry that needs a private channel, not only security disclosures). For non-confidential inquiries, open an [Issue](../../issues).

This policy may be updated as the project matures. Material changes will be announced in [ROADMAP.md](ROADMAP.md) and the project repository.
